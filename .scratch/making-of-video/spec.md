# Spec: 인스타 자동 포스팅 제작기 영상

Status: needs-triage

## 무엇을 만드나

인스타그램 글 자동 포스팅 기능을 **제로베이스(빈 저장소, 첫 커밋 전)부터** 단계적으로 실제 개발하는 과정을 담은 제작기 영상 **1편**. HyperFrames로 만든다.

## 확정된 것

- 목적: **발표용**. 사용자와 비슷한 수준의 주니어 개발자, 개발자 교육생 앞에서 튼다. 조회수용 쇼츠가 아니다 (v1 60초판은 이 점을 잘못 잡았다)
- 내레이션: Edge TTS 한국어, 해요체. 쇼츠식 의미 축약 자막은 쓰지 않는다
- 길이: 훨씬 길게 (레퍼런스는 약 13분). 정확한 길이는 STORYLINES v2에서 정한다
- 레퍼런스(단테 RAG 영상)의 강의 구조를 더 참고한다
- 포맷: 가로 16:9, 1920×1080, 30fps (사용자가 정함. 처음엔 사용자가 고르지 않았는데 세로 9:16을 확정처럼 적었다가, 사용자 요청으로 가로로 바꿨다)
- 영상 수: 1편
- 내용: 단계적 개발, 시행착오, 기능 구현에 대한 고찰, 그리고 다시 개발
- 넣지 않는 것: 날짜, 기간, "N일차" 같은 일정 표기
- 소재: 실제 개발 과정에서 나온 것만 사용 (실제 코드, 터미널 출력, 에러 메시지, 커밋, 실제 포스팅 결과)

## 가정 (바꿔도 됨)

- ~~길이: 45~75초~~ (v1 가정, 폐기)
- ~~내레이션 없음~~ (v1 가정, 폐기)
- 안전 영역: 글자와 핵심 화면은 title-safe(80%, x 192~1728, y 108~972) 안에 둔다

## 진행 방식

1. **개발하면서 소재 쌓기**: 개발 단계마다 `devlog.md`에 기록하고, 스크린샷과 출력은 `captures/`에 저장한다 (기록 규칙은 `devlog.md` 맨 위 참고)
2. **개발이 끝나면 스토리라인 3개**: 실제로 일어난 시행착오를 바탕으로 `STORYLINES.md`를 쓰고, 하나를 고른다
3. **SPEC.md**: 고른 스토리라인을 장면과 프레임 단위로 구체화한다
4. **제작**: HyperFrames 프로젝트(`video/`)를 만들고 check, snapshot, review를 돌린 뒤 미리보기로 확인한다
5. **렌더**: 미리보기를 승인받은 뒤 최종 렌더

## 이야기의 뼈대 (후보)

영상을 관통하는 실제 데이터 하나가 처음부터 끝까지 따라가야 한다. 후보는 **자동으로 올라갈 첫 번째 인스타 게시글 한 건**이다. 처음에는 실패하고, 시행착오를 거쳐 마지막에 실제로 게시된다.

첫 화면 후보: 실제로 게시된 결과물, 또는 첫 번째 실제 에러 화면.

## 레퍼런스 (참고만, 확정 아님)

사용자 메모: "좋은 레퍼런스는 아닐 수도 있음". 아래 내용은 후보 중 하나일 뿐이다. 스토리라인 3개를 쓸 때 이 방향을 따른 안은 최대 하나만 두고, 나머지 둘은 레퍼런스와 무관하게 짠다.

https://youtu.be/iI1k9-VzQMY (단테, "임베딩과 RAG, 13분 만에 이해하기", 가로 13분 설명 영상)

화면을 몇 장 살펴보고 가져올 점을 정리했다 (1:00, 3:00, 5:00, 7:00, 10:00):

- **바탕**: 짙은 초록 칠판 톤 바탕 위에 둥근 모서리 패널 하나. 화면은 늘 그 패널 안에서 바뀐다
- **머리 영역**: 왼쪽 위에 큰 제목(굵은 고딕)과 옆에 작은 섹션 라벨("오늘 볼 것", "자료에 없다"). 섹션 라벨이 지금 위치를 알려 준다
- **로드맵**: 번호 달린 원형 아이콘 세 개를 선으로 이은 진행 지도, 현재 단계에 강조색. 세 단계로 짠 목차
- **실제 코드와 터미널**: 실제 파이썬 코드와 실행 결과를 패널 가득 보여 주고, 핵심 줄은 노란 테두리나 강조색으로 짚는다
- **자막**: 아래쪽 반투명 띠에 말자막
- **캐릭터**: 구석에 작은 픽셀 캐릭터 (반복해서 나오는 마스코트)

**우리 영상에 옮길 때** (가로 16:9, 60초 안팎, 내레이션 없음):
- 칠판 톤 바탕 + 패널 하나라는 "홈 무대"를 가져오되, 16:9로 다시 짠다. 머리 영역은 108px 아래부터
- 로드맵은 개발 단계 지도가 된다. 단계마다 원이 하나씩 켜지고, 시행착오 단계는 빨간 원으로 남는다
- 실제 코드, 실패한 테스트 출력(빨강), 통과한 출력(초록), 에러 원문을 패널 가득 보여 주고 한 줄을 짚는다. TDD의 red → green이 영상의 리듬이 된다
- 말자막 대신 큰 자막 한 줄 (devlog의 `> 자막:`)
- 색, 폰트, 캐릭터는 그대로 베끼지 않고 우리 것으로 정한다 (SPEC.md 단계에서)
