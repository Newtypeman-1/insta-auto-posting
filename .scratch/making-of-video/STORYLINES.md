# Storylines: 인스타 자동 포스팅 제작기

가로 16:9, 1920×1080, 30fps (처음엔 세로 9:16으로 썼다가 사용자 요청으로 바꿈). 영상 하나. 날짜나 기간은 넣지 않는다.
**가정**: 길이 50~70초. 내레이션 없이 큰 자막과 화면 속 실제 텍스트로 전달하고, 음악과 효과음은 무료 소스를 쓴다(유료 항목 없음). 화면에 나오는 에러, 숫자, 출력은 전부 devlog와 captures에 있는 실제 값만 쓴다.

세 안은 같은 사실(S01~S14)을 쓰지만, 서로 다른 세 편의 영상이다.

## B. 글 한 건의 여행 — 추천

*추천 이유: 처음 보는 사람도 "이 글 한 건이 올라갈까?"라는 질문 하나만 따라가면 되기 때문이다.*

**장치**: 한 물건이 앱들을 건너간다. 물건은 첫 번째 게시글 카드 한 장(노트북 사진 + `자동으로 올라간 첫 번째 글 #autopost`)이다. **형식**: 물건에서 물건으로 이어지는 체인. 각 장면은 다음 장면을 여는 물건에서 끝난다.
카드 한 장이 큐 → 검증 → 컨테이너 → 대기 → 게시를 거쳐 폰 화면까지 간다. 시행착오가 생길 때마다 카드가 튕겨 돌아온다. 같은 글이 두 장으로 복제되기도 하고(`assert 2 == 1`), 시간대 없는 시계 앞에서 멈추기도 하고, 문이 쾅 닫히기도 한다(`code 190`). 보는 사람은 카드가 문을 하나씩 통과할 때마다 함께 안도한다.

**첫 2초**: 프레임 0은 빈 터미널 한 줄 `fatal: 현재 'main' 브랜치에 아직 아무 커밋도 없습니다` 위에 카드 한 장이 툭 떨어지는 장면이다. 자막 "글 하나 올리는 데". 1초 지점에 카드 위로 인스타 로고 자리가 비어 있고 "사진이 없으면 못 올린다"(S01)가 뜬다.

**흐름**: 빈 저장소에 카드가 떨어짐 → 테스트가 먼저 빨갛게(S02) → 카드가 두 장으로 복제(S03) → 시간대 없는 시계에 걸려 큐 전체가 멈춤(S07) → 컨테이너 상자 앞에서 기다림, 그리고 영원히 도는 시계(S08, S09) → Meta의 문이 닫힘 `code 190`(S10) → 계정과 메뉴의 벽(S11, S12, 각 1초) → 같은 문이 열림 `quota 0/100`(S13) → 카드가 폰으로 들어가 실제 게시물이 됨(S14, 정상 속도로 크게) → 자막 "한 번에 올라갔다" → 끝 카드

**룩**: 사진 속 세계를 그대로 무대로 쓴다. 따뜻한 나무색과 오프화이트 바탕, 흰 카드, 터미널 텍스트는 카드 위에 인쇄된 듯 진한 먹색 모노체로 넣는다. 강조색은 빨강(실패)과 인스타 핑크(성공) 둘만 아껴 쓴다.

**사운드**: 담백한 로파이 비트에, 카드가 튕길 때 둔탁한 '퉁' 소리, 문이 열릴 때 짧은 상승음, 게시되는 순간 음악이 한 박자 비었다가 다시 들어온다.

## A. 빨간불 다섯 번, 초록불 한 번 — 과감한 안

**장치**: 결과가 먼저 나온다. **형식**: 박자에 맞춘 컷. 화면 전체가 빨강과 초록 색면으로 바뀐다.
실제로 올라간 게시물로 시작했다가 "사실은" 하고 되감는다. 그 뒤로는 실제 실패 출력이 화면 가득 큰 글씨로 한 줄씩 박히고, 박자마다 화면 전체가 빨강 → 초록으로 뒤집힌다. 에러 문장 자체가 주인공인 타이포 영상이다.

**첫 2초**: 프레임 0은 인스타 게시물 화면(S14 스크린샷)이 꽉 찬 장면이다. 자막 "자동으로 올라갔다". 1.2초 지점에 화면이 테이프 되감기처럼 거꾸로 빨려 들어가며 빨간 색면이 되고, 그 위에 `ModuleNotFoundError`가 박힌다.

**흐름**: 결과 → 되감기 → `ModuleNotFoundError`(빨강) → 초록 → `assert 2 == 1`(빨강) → 초록 → `TypeError: can't compare offset-naive and offset-aware datetimes`(빨강, 글자가 화면을 넘칠 만큼 길게) → 초록 → `IndexError: pop from empty list`(빨강) → 초록 → `code 190`(빨강) → `quota_usage: 0`(초록) → 다시 게시물 → 자막 "실패를 먼저 다 겪었다" → 끝 카드

**룩**: 순수한 빨강과 초록 색면, 아주 크고 굵은 모노체, 사진이나 패널 없음. 글자가 프레임 가장자리를 잘라 먹을 정도로 크다.

**사운드**: 빠른 비트(120~130 BPM). 빨강일 때 버저음, 초록일 때 맑은 딩. 마지막 게시물 장면에서만 박자가 느려진다.

## C. 칠판 강의 — 레퍼런스 방향

*레퍼런스(단테, 임베딩과 RAG)에서 구조만 가져온 안. 레퍼런스가 모호하다는 메모가 있어 셋 중 하나로만 둔다.*

**장치**: 질문과 입력. "글 하나를 자동으로 올리려면?" **형식**: 하나의 프레임이 계속 재구성된다. 칠판 패널 하나를 끝까지 떠나지 않는다.
짙은 칠판 패널 위에 개발 단계 지도가 세로로 그려진다. 단계마다 원이 하나씩 켜지는데, 시행착오 단계는 빨간 원으로 남는다. 각 단계에서 패널이 실제 코드나 테스트 출력으로 바뀌고, 한 줄에 형광펜이 그어진다. 마지막에는 지도 전체가 한눈에 보인다. 빨간 원이 초록 원보다 많다.

**첫 2초**: 프레임 0은 칠판 패널 위쪽의 제목 "글 하나를 자동으로 올리려면?", 그 아래 빈 원 하나와 `커밋 0개`라는 글자다. 1초 지점에 첫 원에서 선이 아래로 뻗기 시작한다.

**흐름**: 질문 → 지도 그리기 시작 → 코드 패널 `test_due_post_is_published`(S02) → 빨간 원: 중복 게시(S03) → 빨간 원: 시간대(S07) → 빨간 원: 영원한 대기(S09) → 빨간 원: 계정/메뉴(S11, S12) → 초록 원: 첫 게시(S14) → 지도 전체 → 자막 "빨간 원이 더 많았다" → 끝 카드

**룩**: 짙은 칠판색 패널 하나, 분필 같은 손글씨 선, 코드는 큰 모노체, 형광펜 노랑 강조. 색과 폰트는 레퍼런스를 베끼지 않고 새로 정한다.

**사운드**: 차분한 피아노 루프, 분필이 긁히는 소리, 원이 켜질 때 작은 '톡'.
